# Event registration site — Spec

**Status:** ready-for-agent
**Feature slug:** `event-registration`
**Source:** grilled design session; detailed technical reference in `spec.txt`

## Problem Statement

現有社群活動報名依賴 LINE 的「活動」功能，但它的選項設計不足：只能讓參加者填一個答案，無法處理「出席與否」加上「主餐、飲料」等多組單選需求；主辦者也難以取得即時、可匯出的統計。參與者則常因需要註冊帳號而放棄報名。主辦者需要一個低摩擦、可自架、能即時看到名單與餐點數量的報名網站。

## Solution

一個以 Docker 交付、部署於 VPS 的報名網站。主辦者（單一管理員）建立活動與多個單選選項群組，取得一組秘密公開連結；參與者開連結、答一題二位數加法、輸入姓名即可報名，並能立即看到即時名單與統計。活動可設定截止時間或手動關閉；所有報名資料可匯出 CSV／JSON。系統以伺服器端渲染實作，手機優先、無需 JavaScript 也能完成報名。

## User Stories

1. 作為參與者，我想要在手機上開啟活動連結就看到標題、時間、地點與說明，以便判斷是否參加。
2. 作為參與者，我想要用一題簡單加法取代註冊帳號，以便在幾秒內開始報名。
3. 作為參與者，我想要在答錯時看到清楚的提示並自動換一題，以便重新嘗試。
4. 作為參與者，我想要輸入姓名就能報名，以便主辦者能在名單上認出我。
5. 作為參與者，我想要明確選擇「出席」或「不出席」，以便主辦者知道人數。
6. 作為參與者，我想要在出席時從每個餐點群組各選一個選項，以便主辦者正確備餐。
7. 作為參與者，我想要在選填群組中表達「不選」，以便不被強迫做無關的選擇。
8. 作為參與者，我想要填寫一則簡短備註（例如「不要辣」），以便主辦者處理特殊需求。
9. 作為參與者，我想要在選擇「不出席」時不必看到餐點選項，以便表單保持簡潔。
10. 作為參與者，我想要送出後直接看到包含自己資料的即時名單，以便確認報名成功。
11. 作為參與者，我想要用原瀏覽器的報名 cookie 確認修改同一筆報名，以便避免其他人冒名覆蓋。
12. 作為參與者，我想要在無法驗證既有報名時只看到一般提示，以便既有資料不會洩露。
13. 作為參與者，我想要遺失報名 cookie 時能聯絡管理員協助，以便處理換裝置或清除瀏覽器資料的情況。
14. 作為參與者，我想要再次開啟連結時看到上次填寫的內容，以便快速修改。
15. 作為參與者，我想要隨時查看目前名單與統計，以便知道還有誰參加。
16. 作為參與者，我想要看到每個餐點選項目前的人數與比例，以便了解整體情況。
17. 作為參與者，我想要在活動截止後仍能查看名單，但無法再送出，以便確認最終結果。
18. 作為參與者，我想要在沒有 JavaScript 的瀏覽器上完成報名，以便在受限環境仍可使用。
19. 作為參與者，我想要在手機上以卡片而非寬表格閱讀名單，以便單手操作。
20. 作為參與者，我想要名單只顯示姓名與選項、不顯示任何聯絡資訊，以便安心報名。
21. 作為管理員，我想要用單一密碼登入後台，以便管理活動而不需維護帳號系統。
22. 作為管理員，我想要建立活動並同時建立多個群組與選項，以便一次設定好餐點選擇。
23. 作為管理員，我想要取得可複製的秘密公開連結，以便傳給參加者。
24. 作為管理員，我想要重新產生連結並讓舊連結立即失效，以便在連結外流時補救。
25. 作為管理員，我想要在活動開放後仍能新增或停用選項，以便臨時調整菜色。
26. 作為管理員，我想要在停用已被選擇的選項時看到警告與二次確認，以便知道歷史資料會保留。
27. 作為管理員，我想要手動開放、關閉與重新開放活動，以便控制報名期間。
28. 作為管理員，我想要設定報名截止時間，以便時間到自動停止收單。
29. 作為管理員，我想要複製既有活動（含選項）為新活動，以便重複舉辦相同的聚餐。
30. 作為管理員，我想要查看即時名單與統計，以便掌握最新報名狀況。
31. 作為管理員，我想要匯出 Excel 可直接開啟的 CSV，以便離線統計與訂餐。
32. 作為管理員，我想要匯出完整 JSON，以便備份或與其他系統交換資料。
33. 作為管理員，我想要刪除單筆報名，以便移除誤填或重複的資料。
34. 作為管理員，我想要代為新增或修改報名，以便處理電話或口頭報名。
35. 作為管理員，我想要未登入時被導向登入頁，以便後台不暴露給一般訪客。
36. 作為管理員，我想要登入嘗試受到限速保護，以便降低密碼被暴力猜測的風險。
37. 作為維運者，我想要用一個 compose 指令啟動含自動 TLS 的網站，以便快速上線。
38. 作為維運者，我想要在既有反向代理的 VPS 上只綁本機埠，以便與其他網站共存。
39. 作為維運者，我想要用一支部署腳本更新並在健康檢查失敗時回滾，以便安全改版。
40. 作為維運者，我想要每日自動備份資料庫並保留 30 天，以便意外時可還原。
41. 作為維運者，我想要健康檢查端點與日誌輪替，以便監控與避免磁碟被日誌塞滿。
42. 作為維運者，我想要所有時間以台北時區顯示、資料庫存 UTC，以便跨時區部署仍一致。
43. 作為參與者，我想要名單每 30 秒自動更新，以便在活動現場看到最新狀態。

## Implementation Decisions

### 架構與模組

- 以 Python 3.12、FastAPI、Jinja2 伺服器端渲染實作；無前端框架、無 build step；僅用少量原生 JS 做「不出席時隱藏餐點群組」的體驗優化，核心流程不依賴 JS。
- 應用程式以 **app factory** 建立，接受可注入的設定：資料庫路徑、時鐘、數學題產生器、管理員密碼、session 簽章金鑰。正式啟動與測試走同一條建立路徑。
- 概念模組：活動管理、報名服務（驗證、同名覆蓋、交易寫入）、統計、匯出、驗證與 session、限速、儲存層。模組之間以服務函式介面互動，路由層只負責 HTTP 與模板。
- SQLite（WAL、`busy_timeout`）為唯一儲存；報名寫入在單一交易中完成「查同名 → 新增或更新 → 寫入選擇」。

### 資料模型

- **活動**：token（10 碼不可猜測，去掉易混淆字元）、標題、說明、地點、開始時間、報名截止時間、狀態（`draft`／`open`／`closed`）、建立與更新時間。
- **選項群組**：所屬活動、類型（`attendance`／`custom`）、標題、是否必填、排序。每個活動自動建立一個不可刪除、固定必填的出席群組。
- **選項**：所屬群組、文字、啟用旗標（軟刪除）、排序。出席群組固定「出席」「不出席」兩個不可變更的選項。
- **報名**：所屬活動、姓名、正規化姓名、出席狀態、備註、建立與更新時間；`(活動, 正規化姓名)` 唯一。
- **報名選擇**：只保存自訂群組答案；出席狀態僅由報名的出席欄位決定。選擇資料保存送出當時的群組與選項文字快照。
- 姓名正規化：NFKC、去前後空白、連續空白合併、Latin 字母 casefold；同名視為同一人，不同參與者同名時由管理員將其中一筆改成可區分的姓名。
- 時間以 UTC ISO 8601 儲存，顯示轉 `Asia/Taipei`（`YYYY-MM-DD HH:MM`）。

### 存取與 session

- 參與者：活動頁首次進入需答一題二位數＋一位數、和 ≤ 100 的加法；答案存於簽章 session，答對後該瀏覽器 24 小時內免再答。驗證只是防機器人，不具身分意義。
- 管理員：單一密碼以常數時間比較，登入後 session 12 小時；登出清除目前瀏覽器 cookie，已複製的無狀態 session 可用至到期；更換密碼使舊 session 立即失效。未登入存取管理路由一律導向登入頁。
- Cookie 一律 `HttpOnly`、`SameSite=Lax`，偵測 HTTPS 時加 `Secure`；所有 POST 表單帶 CSRF token。
- 限速以程序內計數器實作：管理員登入 5 次/分/IP、報名送出 20 次/分/IP、數學題送出 20 次/分/IP。
- 只有明確設定的可信反向代理可提供客戶端 IP；其他轉發標頭不可信。

### 活動生命週期與選項

- 狀態機：`draft` → `open` → `closed`，可雙向重開；`draft` 對公開連結顯示「尚未開放」。
- 截止時間在每次請求時由伺服器時鐘判斷，不依賴排程或前端倒數；到達即拒絕送出，但名單仍可讀。
- 自訂群組只在出席時顯示與送出；後端以出席狀態為準，忽略不出席時送來的自訂選擇。
- 選項刪除採停用；停用選項不出現在表單，但歷史選擇保留並在統計標示「已停用」。
- 群組必填／選填由管理員設定；選填群組提供明確的「不選」，未選時不建立選擇列。

### 報名流程

- 單頁表單：活動資訊 → 姓名 → 出席群組 → 自訂群組 → 備註 → 送出；另有「已報名資料」按鈕。
- 送出時伺服器端驗證：活動為開放且未過截止、姓名長度、必填群組、選項歸屬與啟用狀態、備註長度。
- 同名存在且瀏覽器 cookie 指向該報名時，才顯示覆蓋確認；否則不洩露既有資料並提示聯絡管理員。並行建立撞上唯一性限制時也不覆蓋資料。
- 報名 cookie 綁定報名 ID；遺失 cookie 或換裝置時由管理員協助。改名後原 cookie 仍可編輯該報名。
- 覆蓋確認後更新該筆並保留 `created_at`；送出與覆蓋成功皆導向名單頁。
- 驗證與錯誤一律以同頁重繪呈現並保留已填內容；錯誤頁提供返回連結。

### 名單與統計

- 名單頁對所有持有活動連結且通過數學題者公開：姓名、出席狀態、各群組選擇、備註、最後更新時間，依建立時間排序；不含聯絡資訊或 IP。報名前告知可見對象與欄位，提醒備註勿填敏感資料。
- 統計：總筆數、出席數、不出席數、出席率（整數百分比，0 筆顯示「—」）；每群組各選項人數與佔該群組作答人數的比例；選填群組另列「未選」。
- 桌機以表格、手機以卡片呈現；頁面每 30 秒自動重新整理；提供回首頁／結束按鈕（皆導回報名頁，不用 `window.close()`）。

### 管理員功能

- 活動列表（標題、狀態、報名數、截止時間、可複製連結）、建立／編輯／複製活動、開放／關閉／重開、重新產生 token；v1 不提供刪除整個活動。
- 報名管理：查看、刪除、代為新增與修改（同樣走唯一性與欄位驗證）。
- 匯出 CSV（UTF-8 BOM，群組一欄，停用選項加註）並防止試算表公式注入；資料庫與 JSON 保留原文，JSON 包含完整活動結構與報名。

### 部署與維運

- 單一 compose：app 容器（uvicorn、非 root、`restart: unless-stopped`、healthcheck、256MB 記憶體上限、日誌輪替 10MB×3）＋ Caddy 容器（`DOMAIN` 自動 TLS）。
- 提供 compose 覆寫檔：不啟動 Caddy，app 只綁 `127.0.0.1:APP_PORT`，由既有反向代理轉發。
- 部署腳本：先備份資料庫、記錄目前 image tag → `git pull` → build → `up -d` → 輪詢健康檢查（上限 60 秒）→ 失敗時停止 app、還原資料庫、回滾 image 並再次健康檢查。
- 備份腳本：每日 SQLite 線上快照＋CSV 匯出，保留 30 天；線上刪除不立即清除備份；備份與匯出含個資並需限制存取；異地備份不在範圍。
- 設定只來自 `.env`（管理員密碼、session 金鑰、網域、連接埠、時區），提供範例檔並排除真實 `.env`。

### 安全與輸出

- 全部輸出經模板跳脫；說明與備註視為純文字，不解析 HTML／Markdown。
- 公開連結 token 以 `secrets` 產生；名單頁需先通過數學驗證。
- 不將 IP 寫入資料庫；日誌只記方法、路徑、狀態碼、耗時。

## Testing Decisions

- 好測試只驗證**外部行為**：透過真實 HTTP 路由與表單觀察結果，不直接斷言資料庫內部結構、不 mock 服務層。
- **單一主要 seam：HTTP／ASGI 整合層**。以 app factory 為每個測試建立獨立暫存資料庫的實例，用 TestClient 取得頁面、抽 CSRF token、送出表單、跟隨 redirect，解析 HTML 與匯出檔。
- 同一個 seam 上提供兩項測試注入：**可設定的時鐘**（驗證截止前後）與**可指定的數學題**（讓驗證流程可重現）。不新增其他 seam。
- 涵蓋範圍：
  - 數學題正確／錯誤、未驗證不可送出、session 有效期。
  - 姓名正規化（全形／半形空白、大小寫、NFKC）導致同名覆蓋；覆蓋後僅一筆且 `created_at` 不變。
  - 必填群組缺漏、選填群組留空、備註長度、非法選項。
  - 不出席時自訂選擇不寫入；切回出席可正常送出。
  - `draft` 不可報名、截止後拒絕、重開後恢復、名單在截止後仍可讀。
  - 管理員登入成功／失敗、未登入導向、限速觸發。
  - CSV 欄位、BOM、停用選項標註；JSON 結構；token 重新產生後舊連結 404。
  - 刪除與代改報名、代改時的姓名唯一性。
- **不導入瀏覽器 E2E**；手機版型與 JS 隱藏行為以人工驗收。
- 部署層以 `scripts/smoke.sh` 驗證：compose 啟動後 `/healthz` 回 200、首頁可讀、不存在的活動 token 回 404。

## Out of Scope

- 參與者帳號、密碼、Email／手機驗證、社群登入
- 多選（可勾多個）群組、選項名額上限
- 金流、通知（Email／LINE／簡訊）、候補機制
- 公開活動目錄、搜尋、跨活動報名
- 多管理員、權限分級、操作稽核
- 檔案上傳、圖片、Markdown 說明
- 瀏覽器 E2E、CI/CD、外部 image registry、異地備份
- 多語系（僅繁體中文）

## Further Notes

- `spec.txt` 是本規格的詳細技術參考（欄位、路由表、驗收條件）；本文件是追蹤器上的摘要，兩者衝突時以 `spec.txt` 的具體規則為準。
- 預期規模為單一活動 50–200 人、少量活動並存；單一 uvicorn worker 與 SQLite 足夠。
- 管理員只有一位，密碼輪替＝更新 `.env` 並重啟容器。
- 名單對活動連結持有者公開是刻意取捨；報名前需告知，且不顯示聯絡資訊。
- 選項文字以報名當下快照呈現；已被報名選擇的選項不可直接改名，管理員應停用舊選項並新增替代選項。
